# 설계 결정 기록

결정 하나당 한 항목. 뒤집힌 결정은 지우지 않고 "→ D-0XX로 변경"을 덧붙인다.
조인 테이블 채택의 상세 근거는 [ADR-001](adr/ADR-001.md) 참고.

| 번호 | 결정 | 근거                                                                                                                                                                                                                             |
|---|---|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| D-001 | 이 서비스는 자격을 "판정"하지 않고 후보를 "좁히는 필터"다 | 자격 조건 일부가 자유 서술이라 기계가 확정할 수 없다                                                                                                                                                                                                 |
| D-002 | 매칭 결과는 3가지 상태: 충족 / 미충족 / 판단불가 | 소득 조건의 9%가 숫자 없이 글로만 적혀 있다                                                                                                                                                                                                     |
| D-003 | 자유 서술 필드는 해석하지 않는다. `addAplyQlfcCndCn`이 비어 있지 않으면 "확인 필요" 표시 | 자연어 해석은 오판 위험이 크고 범위 밖이다                                                                                                                                                                                                       |
| D-004 | 전량 정규화 대신 30건 큐레이션 | 9월 일정 안에 정확도를 확보하기 위함                                                                                                                                                                                                          | 전량 정규화 대신 30건 큐레이션 → D-014로 변경                                                                                                                                                                                                         |
| D-005 | 서비스 범위는 중분류 4개로 제한 | 금융·주거 지원에 집중 | 서비스 범위는 중분류 4개로 제한 → D-014로 변경                                                                                                                                                                                                                  |
| D-006 | 소득은 구분 코드(`earnCndSeCd`)로 분기한다. 중위소득 환산은 하지 않는다 | 0043001 무관 / 0043002 연소득 숫자 비교 / 0043003 기타 → 판단불가                                                                                                                                                                             |
| D-007 | 승인된 정책(`plcyAprvSttsCd=0044002`)만 저장 | 미승인 정책은 노출 대상이 아니다                                                                                                                                                                                                             |
| D-008 | 마감된 정책은 DB에서 지우지 않고 조회할 때 제외 | 배치를 다시 돌려도 결과가 같아야 한다(멱등성)                                                                                                                                                                                                     |
| D-009 | 기술 차별점은 자연어 해석이 아니라 범위 조건 인덱스 최적화 | D-003과 같은 이유                                                                                                                                                                                                                   |
| D-010 | 성능 실험은 실제 데이터로 한다 | 가짜 데이터는 분포가 달라 결과를 믿을 수 없다                                                                                                                                                                                                     |
| D-011 | 대상 분류 범위는 설정 파일로 관리 | 범위를 바꿀 때 코드를 고치지 않기 위함                                                                                                                                                                                                         |
| D-012 | 취업 상태 축은 9/25 보류. 현재 매칭은 3축(나이 · 시도 · 소득). 수집한 값은 `policy_job` 테이블에 그대로 둔다. 코드 뜻을 명세로 확인하면 구현한다 | 취업 상태 코드(`0013010` 등)의 뜻이 확인된 것이 아니라 빈도로 추측한 것이다. 추측으로 조건을 걸면 자격 없는 사람에게 "충족"이 뜨거나 자격 있는 사람의 정책이 결과에서 빠진다. 조건을 걸지 않으면 결과가 넓어질 뿐 틀린 안내는 없다(D-001)                                                                               |
| D-013 | 배포는 PR이 `main`에 머지되고 CI가 통과했을 때만 자동으로 실행한다. 이미지 태그는 커밋 SHA를 쓴다(`lhjunkr/policy-match:<SHA>`). 문제가 생기면 서버에서 `deploy.sh <이전 SHA>`로 이전 이미지로 되돌리고, `main`의 문제 커밋도 되돌린다. 서버가 2대 이상이 되거나 DB 변경이 잦아지면 다시 검토한다 | `feature` 브랜치나 PR 단계에서 배포하면 검토와 테스트가 끝나지 않은 코드가 공개 URL에 올라간다. `latest`는 같은 이름이 매번 다른 내용을 가리켜, 서버가 어느 커밋을 돌리는지 알 수 없고 되돌릴 대상도 없다. SHA 태그는 커밋마다 하나씩 남으므로 다시 빌드하지 않고 태그만 바꿔 되돌릴 수 있다. 단, 되돌아가는 것은 앱뿐이고 Flyway가 적용한 DB 변경은 그대로 남는다 |
| D-014 | 매칭 대상을 30건 큐레이션 대신 규칙으로 고른다. 규칙은 승인된 정책(D-007) 중 중분류 3개(취약계층 및 금융지원 · 주택 및 거주지 · 전월세 및 주거급여 지원)에 속하고 가장 최근 수집에서 확인된 정책이며, 건수 상한은 두지 않는다. 마감 여부는 정규화에서 보지 않고 매칭할 때만 거른다(D-008 유지). 규칙에서 빠진 정책은 지우지 않고 `active = FALSE`로 표시해 매칭에서 제외하고, 다시 규칙에 들면 `TRUE`로 되돌린다. 비활성 처리는 수집이 끝까지 성공했을 때만 실행한다 | 기존 30건은 사람이 고른 것이 아니라 정책번호 순 앞 30건이었고 마감일을 보지 않아 17건이 만료, 25세·서울 결과가 1건이었다. 같은 분류 안에 신청 가능한 정책이 387건(9/25, 상시 329 + 진행중 58) 있다. 마감 필터를 정규화에도 넣으면 다음 날 마감되는 정책 때문에 매칭 단계 필터가 어차피 필요해 같은 규칙이 두 곳에 생긴다. upsert는 행을 지우지 않으므로 승인 취소·분류 변경·API 삭제 정책이 계속 노출되고, 삭제하면 연결 표를 먼저 지워야 하며 다시 나타날 때 id가 바뀐다. 대가: 수백 건이라 수동 보정을 할 수 없어 판단불가와 "확인 필요"가 늘어난다. 수집이 중간에 끊기면 정상 정책이 대량으로 비활성될 수 있어 안전장치가 필요하다 |
