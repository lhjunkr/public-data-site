# ADR-001: 다중값 필드를 연결 표로 정규화한다

- 상태: Accepted
- 날짜: 2026-09-08

## 맥락

청년정책 API는 한 정책이 적용되는 지역을 `zipCd` 필드에 콤마로 구분된 문자열로 준다.

```
"zipCd": "11110,11140,11170,...,52800"
```

정책 하나가 수백 개의 법정동 코드를 갖는다. `jobCd`(취업상태)에서도 같은 형태가 확인됐다.

이 서비스의 핵심 기능은 "사용자의 나이·지역에 해당하는 정책 찾기"이므로, 지역은 검색 조건으로 직접 쓰인다.

## 결정

콤마 문자열을 그대로 저장하지 않고, **연결 표 `policy_region`으로 분해해 행 단위로 저장한다.**

## 근거

db-fiddle에서 두 방식을 직접 구현해 비교한 결과다.

**1. 검색이 정확하고 빠르다**

콤마 방식은 `LIKE '%27110%'` 부분 일치로만 검색 가능해 다른 코드까지 걸린다. 또한 `%`로 시작하는 `LIKE`는 인덱스를 쓸 수 없어 전체 스캔이 발생한다. 연결 표는 `= '27110'`으로 정확히 일치하며 인덱스를 탄다.

**2. 집계가 가능하다**

`GROUP BY`로 지역별 정책 수를 즉시 구할 수 있다. 콤마 방식으로는 이 질의에 답할 표준적인 방법이 없다. 이 서비스는 결과를 카테고리별 건수와 함께 제시하므로 집계가 필수다.

**3. 무결성을 DB가 보장한다**

외래 키로 존재하지 않는 지역 코드를 거부한다. 콤마 방식은 오타를 그대로 통과시키고, 오염은 나중에 검색 결과가 틀어질 때야 발견된다. 실제로 오타를 넣은 뒤 `LIKE` 검색을 하면 잘못된 행이 결과에 섞이는 것을 확인했다.

## 검토한 대안

**대안 1 — 콤마 문자열 그대로 저장**

구현이 가장 단순하다. 그러나 위 세 가지 문제로 서비스의 핵심 기능인 지역 검색이 성립하지 않는다. 기각.

**대안 2 — 지역 열을 `region_1`, `region_2`, ... 로 나열**

정책마다 적용 지역 수가 다르고 수백 개까지 가므로 열 개수를 고정할 수 없다. 기각.

## 결과

**얻는 것**

- 지역 기반 검색이 인덱스를 타고 정확히 동작
- 지역별·카테고리별 집계 가능
- 잘못된 지역 코드가 저장되지 않음

**치르는 대가**

- 표가 늘어나고 조회 시 `JOIN`이 필요하다
- 수집 단계에서 콤마를 분해하는 처리가 추가된다
- `region` 마스터 표를 채울 법정동 코드 목록을 별도로 확보해야 한다

**적용 범위**

`zipCd`만 연결 표로 분해한다. `jobCd`도 다중값이지만 100건 표본에서 96%가 단일 기본값이라 필터로서 변별력이 없어 정규화하지 않고 `policy_raw`에만 보존한다. 필터로 쓸 근거가 생기면 그때 정규화한다.
