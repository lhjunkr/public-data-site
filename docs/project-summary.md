# 프로젝트 한눈에 보기 — 기능 · 수치 · 사건 · 결정 (2026-09 ~ 11)

이 서비스를 만들고 운영하며 나온 **기능, 측정한 수치, 겪은 사건, 내린 결정**을 한 문서에 모았다.
각 줄의 근거는 맨 오른쪽 칸의 문서에 있다. 서버 주소 · 비밀값처럼 공격에 쓰일 수 있는 값은 적지 않는다.

### 성능 — 측정으로 병목을 찾아 하나씩 ([performance](performance.md), D-027)

| 항목 | Before (11/10) | After (11/22) | 변화 |
|---|---|---|---|
| 처음 방문 응답 (p50) | 1,173.6ms | **353.8ms** | −70% |
| 서버 처리 (서버 안 p50) | 556.6ms | 61.1ms (②까지) | −89% |
| 응답 크기 | 356.4KB | **27.9KB** | −92% |
| 동시 5명 처리량 | 초당 1.37건 | **초당 10.49건** | 7.7배 |
| 동시 10명 응답 중앙값 | 6.87초 | **0.85초** | −88% |
| 매칭 SQL (`EXPLAIN ANALYZE`, 25세 · 경기) | 1,179ms | 83ms | 조건 4개 모두 기준 100ms 이하 |

- 짐작한 병목(나이 · 마감 범위 인덱스)은 SQL의 약 2%였고, **93%가 지역 확인**(정책 × 시군구 코드 57,700번)이었다 → 시군구 211,668행을 시도 단위 14,719행(−93%)으로 저장해 해결.
- 개선마다 **결과를 먼저 예측하고** 같은 조건으로 다시 쟀다. 마지막 압축 예측 350 ~ 420ms → 실측 353.8ms.
- 전송 시간은 크기가 아니라 왕복 횟수를 따랐다(크기 −55%에 전송 −23%). 지금 354ms의 약 83%는 서울 ↔ 도쿄 거리 몫이다.
- 처리량의 한계는 끝까지 DB 서버 CPU(무료 1/8 OCPU)였다.

| 11/06 | 계획된 DB 정지 시험이 58분 중단이 됨 | 감지는 2분이었으나 확인 · 재시작이 늦음 | 계획 점검으로 기록. 일부러 멈추는 실험은 타이머를 맞추고 자리를 지킴 |
| 11/24 | 복원 리허설에서 백업 암호가 서버 밖에 없음을 발견 | 만들 때 비밀번호 관리자에 저장하지 않음 | 서버 설정에서 되찾아 서버 밖에 보관. 암호가 틀려도 오류 없이 빈 목록이 나오는 동작도 발견 → 복원 전 확인 절차 추가 |

## 5. 설명할 수 있는 결정

| 주제 | 결정과 이유 | 근거 |
|---|---|---|
| 판정하지 않고 좁힌다 | 받을 수 있는 정책을 잘못 빼는 것이 더 나쁘다. 비교할 수 없으면 결과에 남기고 판단불가 | D-001, D-002 |
| 다중값은 연결 표 | 콤마 문자열은 정확한 검색 · 집계 · 무결성 검사를 모두 잃는다 | ADR-001 |
| `JOIN` 대신 `EXISTS` | 전국 정책 1건이 서울 25개 구와 짝지어져 25줄이 됨 → "하나라도 있는가"만 봄 | [retrospective](retrospective.md) |
| 입력 검증을 SQL 앞에 | 문자열 `"NULL"`이 오류 없이 0이 되어 "충족"이 나오는 것을 직접 확인 | [retrospective](retrospective.md) |
| 멱등성은 스키마에 | UNIQUE + `ON DUPLICATE KEY UPDATE`. 연결 표는 달라졌을 때만 비우고 다시 채워 줄어든 값도 반영 | [retrospective](retrospective.md) |
| 원본 보관 | 규칙을 바꾸면 다시 수집하지 않고 정규화만 다시 | D-008 |

| 한 번에 하나만 | 정규화(약 70초)가 MySQL 잠금 대기 한도(50초)보다 길어 겹치면 뒤의 것이 실패 → 원자적 잠금 + 409 | D-020 |
| 측정 먼저 | 처음 정한 "범위 인덱스 최적화"(D-009)는 겨냥한 곳이 틀렸음을 실행 계획으로 확인하고 바꿈 | D-009 → D-027 |

## 6. 알려진 한계

- 동시 처리량이 초당 약 10.5건에서 DB 서버 CPU에 막힌다.
- 앱이 한 대라 배포 · 재시작마다 수십 초 점검 화면이 나온다.
- 학력 · 전공 · 특화 조건과 시군구 단위 매칭은 아직 하지 않는다.
- 결과가 조회수 순이라 새 정책 · 마감 임박 정책이 뒤로 밀린다(12월 정렬 예정).
- 실사용자 지표가 아직 없다(12월 사용 지표 예정).
- 대량 변경 상한 아래의 부분 손실(분류 하나가 통째로 빠지는 정도)은 감지하지 못한다.
